# QQ Agent 优化与发展路线图

## 愿景

将 QQ Agent 从功能丰富的 QQ 机器人，发展为可安全运营、可持续调优的个人与群聊 AI 助手。

项目已经具备多供应商模型、人格、分层记忆、情绪分析、图片与语音处理、定时任务和管理面板等基础能力。后续工作的重点不应只是继续增加功能，而应让已有能力更可靠、更可控，并让用户能明确看见它们带来的价值。

## 优先原则

1. **先可靠，后扩展**：连接、模型调用、数据存储和任务投递出现问题时，必须能发现、定位并恢复。
2. **用户始终掌控数据**：记忆、权限、主动发言和自动任务都应可查看、修改、关闭和删除。
3. **按任务选择能力**：不同模型负责不同工作，避免把高成本模型用于简单任务。
4. **适应群聊场景**：默认克制，减少无关打断；群主和管理员可以按群配置行为。
5. **让维护成本随功能增长保持可控**：模块边界、测试、日志和诊断能力要与业务能力同步演进。

## 发展阶段

| 阶段 | 目标 | 重点工作 |
| --- | --- | --- |
| 近期 | 稳定、易用、可诊断 | 启动自检、健康检查、面板诊断、模型降级状态、配置变更记录 |
| 中期 | 让记忆和群聊能力真正有价值 | 可解释记忆、群级策略、日报与摘要、模型任务调度、成本控制 |
| 后期 | 可扩展、可部署、可运营 | 插件与工具机制、外部服务集成、部署与备份、多实例管理 |

## 近期：可靠性与可用性

### 1. 健康中心

管理面板应提供统一的健康视图，而不是仅显示是否已连接。

- OneBot 连接状态、最近心跳与重连次数。
- 各供应商、模型和备用模型的连通状态、延迟和最近错误。
- 数据库体积、向量索引状态、待执行任务数量与失败任务数量。
- 最近异常的影响范围、建议处理方式和可复制的诊断信息。
- 一键导出脱敏诊断包，便于排查问题。

### 2. 启动与配置体验

- 启动时检查 Node 版本、配置完整性、数据目录可写性、端口占用与模型配置。
- 将配置错误分为阻断启动、功能降级和提示信息三类。
- 为常见使用方式提供配置模板：个人助手、群聊助手、低成本模式、仅管理员模式。
- 在面板中展示配置变更记录，包含修改时间、字段、旧值和新值；密钥永不展示。

### 3. 失败恢复与降级

- 模型调用失败时清楚标明是否已切换到备用模型。
- 为网络波动、限流、超时和无效响应分别设置合适的重试策略。
- 将无法投递的消息、提醒和任务保留在可靠队列中，支持人工重试。
- 让用户能从面板直接看到失败原因，而不是只能翻日志。

## 中期：记忆与对话质量

### 1. 可解释记忆

记忆是项目的核心差异化能力，也最容易在长期使用中积累噪声。

- 每次回复可查看本次召回了哪些记忆，以及它们对回复的影响。
- 新记忆可以先作为“建议”进入待确认区，再由用户确认是否长期保留。
- 自动识别重复和冲突记忆，例如兴趣、称呼或身份信息前后不一致。
- 支持长期、临时、私密、群共享与已过期等明确状态。
- 支持设置遗忘期限，并为低置信度或长期未命中的记忆提供复核建议。

### 2. 更好的上下文管理

- 区分当前话题、近期上下文、长期记忆和群级知识，避免它们相互污染。
- 对长对话显示压缩摘要，并允许用户查看原消息与摘要的对应关系。
- 在面板中提供“本次回复上下文预览”，便于调试回复质量。

### 3. 质量反馈闭环

- 允许管理员对回复标记“有帮助”“不准确”“不该回复”。
- 汇总低质量回复的场景，关联模型、人格、记忆和触发方式。
- 将匿名化的回放数据用于本地回归测试，避免修复一个问题后引入旧问题。

## 中期：群聊场景与模型调度

### 1. 群级行为策略

每个群都应能独立设置：

- 人格、回复语气、默认模型与最大回复长度。
- 是否必须 @、关键词和前缀触发规则。
- 主动发言频率、免打扰时段和每小时回复上限。
- 允许讨论的话题、敏感话题处理策略和管理员权限。
- 是否记录群聊上下文，以及群级记忆的保留期限。

### 2. 有价值的群功能

- 自动生成群日报：活跃话题、结论、待办事项和待确认问题。
- 对持续讨论的话题建立线程，减少不同话题之间的上下文混淆。
- 在管理员确认后，把明确的决定、规则和待办写入群级知识库。
- 提醒用户未完成的待办或即将到期的事项，但避免频繁打扰。

### 3. 按任务调度模型

| 任务 | 调度方向 |
| --- | --- |
| 日常闲聊 | 低延迟、低成本模型 |
| 情绪分析、记忆抽取 | 稳定且成本较低的小模型 |
| 长上下文总结 | 擅长长文本的模型 |
| 图片理解与复杂问题 | 更高能力的视觉或推理模型 |
| 主模型不可用 | 自动降级到备用模型，并记录原因 |

模型调度应支持每日与每月预算、单群额度、单用户额度和异常调用告警。面板应展示实际成本趋势，而不只展示 Token 总数。

## 后期：扩展与产品化

### 1. 插件与工具能力

- 设计稳定的插件接口，允许新增命令、事件处理器、面板页面和外部工具。
- 支持安全的 HTTP/Webhook 工具调用，并限制可访问的地址、权限和调用频率。
- 逐步接入日历、待办、知识库、文件存储等服务。
- 为每种工具提供权限声明、审计记录与禁用开关。

### 2. 部署与数据管理

- 提供 Docker 部署与升级文档。
- 支持配置、数据库和人格文件的一键备份与恢复。
- 提供多机器人实例隔离：每个 QQ 账号拥有独立配置、数据和权限。
- 增加升级前检查与可回滚的迁移机制。

### 3. 工程演进

- 明确平台接入、对话编排、模型调用、记忆、任务和面板 API 的模块边界。
- 为关键事件定义统一结构化日志与指标。
- 对关键用户路径维护端到端回放测试。
- 为配置结构和数据迁移建立版本化机制。
- 将运行期诊断能力作为正式产品能力维护，而不是排障时临时增加的脚本。

## 建议的首批实施项

1. 完善管理面板首页：健康评分、模型可用性、最近失败、任务状态与调用趋势。
2. 加入模型调用的降级链路展示，以及按错误类型统计的失败分析。
3. 实现记忆来源与召回解释页面，并加入记忆待确认机制。
4. 实现群级行为配置，优先覆盖触发规则、主动发言和免打扰时段。
5. 增加 Token/成本预算和异常预警。
6. 建立核心对话链路的回放回归测试，保证后续优化不会降低已有质量。

## 产品取向

QQ Agent 应该“有个性但不过度打扰”。私聊中可以更主动、更具陪伴感；群聊中应默认克制、尊重上下文和群规则。记忆与自动化应帮助用户，而不是变成不可见、不可控的黑箱。
